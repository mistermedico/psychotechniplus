# בדיקת איכות שאלות לפני ייבוא

כל סקריפט שכותב לטבלה `questions` עובר דרך `scripts/lib/question-import-guard.cjs`.

## מה נבדק (`scripts/lib/question-bank-validator.cjs`)

| בדיקה | חוסם ייבוא? |
|---|---|
| בדיוק תשובה נכונה אחת, ו-`correct_answer` תואם ל-`isCorrect` | כן |
| אין אפשרויות זהות, ריקות או placeholder ("האפשרות הראשונה ברשימה", "- מסיח 4") | כן |
| אין קבוצות מסיחים גנריות ("מכשיר/תוצאה/מקום", "סימן למעלה/סימן למטה"...) | כן |
| חישוב אוטומטי לתבניות מוכרות (אחוזים, שארית, ממוצע משוקלל, משוואות, סדרות, שברים) — התשובה המסומנת נכונה ואין שתי אפשרויות שוות לה | כן |
| שאלה כפולה (טקסט זהה לשאלה אחרת בייבוא או במאגר החי) | כן |
| תמונה: הכותרת שמצוירת בתוך ה-SVG חייבת להתאים לטקסט השאלה | כן |
| תמונה: אותה תמונה לא משמשת שאלות שונות; אין תמונות תשובה זהות | כן |
| רמת קושי 1–10, הסבר קיים | כן |
| תמונה חיצונית (PNG) / תשובות עם טקסט וגם תמונה | אזהרה — בדיקה ידנית |

## הגנות נוספות בזמן ייבוא

- מזהים שנמצאים ב-`admin_state.deleted_question_ids` לא ייובאו מחדש.
- שאלות שכבר קיימות ב-DB **לא נדרסות** כברירת מחדל, כדי שייבוא מקבצי המקור לא יחזיר תיקונים שנעשו ישירות ב-DB. לדריסה מכוונת: `FORCE_OVERWRITE_QUESTIONS=1`.
- `ALLOW_INVALID_QUESTIONS=1` מאפשר ייבוא עם שגיאות רק לשאלות בסטטוס `pending`; שאלה `validated` עם שגיאה תמיד נחסמת.
- הסקריפטים משתמשים ב-`SUPABASE_SERVICE_ROLE_KEY` מהסביבה אם הוגדר (בגלל RLS, מפתח anon לא יכול לכתוב שאלות).

## הרצה ידנית

```bash
npm run validate:questions -- --file questions.json   # לפני ייבוא קובץ
SUPABASE_SERVICE_ROLE_KEY=... npm run validate:questions:live -- --status all   # בדיקת כל המאגר
```

קוד יציאה 1 כשיש שגיאות — אפשר לשלב ב-CI.

בצד האפליקציה, `utils/questionQuality.ts` (עורך השאלות ומסך האישור באדמין) בודק גם הוא התאמה בין כותרת התמונה לטקסט ותמונות תשובה כפולות.

## שאלות צורות אוטומטיות (`scripts/lib/spatial-question-generator.cjs`)

מחולל דטרמיניסטי ל-60 שאלות צורות: שיקוף אנכי/אופקי, סיבוב 90°/180°, זיהוי סיבוב מול תמונת ראי, רצף פעולות, מטריצות 3×3, פריסות קובייה וקיפול דף עם ניקוב.
כל שאלה נבנית ממודל גיאומטרי מדויק (פוליאומינו כירלי + ריבוע סימון, פריסת קובייה, דף מקופל), ולכן התשובה והמסיחים מחושבים ולא מנוחשים.

- `scripts/verify-spatial-questions.cjs` — בדיקה **בלתי תלויה**: קוראת את ה-SVG עצמם (שאלה ותשובות), משחזרת מהם את הגיאומטריה ומחשבת את התשובה במימוש נפרד (קיפול תלת-ממדי לקובייה, קיפול קדימה לדף, התאמת חוק שורה/עמודה במטריצה). נכשלת אם אין בדיוק תשובה אחת מתאימה או אם היא לא המסומנת.
- התמונות לא מכילות טקסט מלבד "?" ומספרי שלבים, כך שבדיקת "כותרת התמונה תואמת לשאלה" לא יכולה להיכשל.
- בבדיקת כפילויות, שאלות עם תמונה נחשבות כפולות רק אם גם הטקסט וגם התמונה זהים (לשאלות צורות יש ניסוח גנרי משותף).
- אפשרויות שמסומנות רק לפי מיקום ("צורה א׳"...) לא מעורבבות באפליקציה (`utils/optionOrder.ts`) — מיקום התשובה הנכונה כבר אקראי, וההסבר מתייחס לאותיות.

```bash
npm run generate:spatial -- --out spatial.json      # יצירה + ולידציה + אימות בלתי תלוי
npm run verify:spatial -- spatial.json               # אימות בלבד
SUPABASE_SERVICE_ROLE_KEY=... npm run generate:spatial -- --import
```
